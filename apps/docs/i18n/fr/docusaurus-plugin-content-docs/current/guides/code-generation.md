# Génération de code

Un contrat écrit en TypeScript ne demande aucune étape de build. Quand la description vient d'ailleurs (un document
OpenAPI, une application NestJS ou Express), Polycanal **génère** un contrat TypeScript lisible, avec des schémas
d'exécution (Zod par défaut), que le front importe comme un contrat écrit à la main.

Un contrat écrit à la main n'importe aucun code serveur : le back et le front importent donc le même fichier depuis un
[package ou un répertoire partagé](../concepts/architecture.md#contrat-partagé), c'est-à-dire un package de workspace
dans un monorepo, ou un package publié sur un registre npm (privé) quand ils vivent dans des repos séparés.

## Depuis OpenAPI

```bash
npm install --save-dev @polycanal/openapi
npx polycanal-openapi openapi.json src/contract.generated.ts --export api
```

Ou par programme :

```ts
import { generateFromOpenApi } from '@polycanal/openapi';

const { source, warnings } = generateFromOpenApi(document, { exportName: 'api' });
```

Les documents OpenAPI 3.0 et 3.1 au format JSON sont pris en charge (convertissez le YAML au préalable si besoin).

- **Noms :** `[premier tag, operationId]` en camelCase (`pets.listPets`) ; sans `operationId`, le nom est construit à
  partir de la méthode et du chemin (`pets.deletePetsByPetId`). Passez `naming` pour le changer.
- **Paramètres :** les paramètres de chemin, de query et d'en-tête deviennent des champs avec leur source ; les noms
  qui ne sont pas des identifiants passent en camelCase avec un alias (`X-Tenant` → `xTenant`).
- **Bodies :** un body JSON objet est étalé en champs `body` ; tout autre body devient un champ racine `body`.
- **Réponses :** la première réponse JSON 2xx est l'output (sans contenu : `z.void()`) ; les réponses JSON 4xx et 5xx
  deviennent des `errors`.
- **Schémas :** `components.schemas` deviennent des constantes exportées (`PetSchema`), les récursifs via `z.lazy()`.
- **Ignorés, avec un avertissement :** les opérations `HEAD`, `OPTIONS` et `TRACE`, les paramètres cookie, les bodies
  de requête non JSON, les paramètres de chemin qui ne sont pas des identifiants.

## Code généré

```ts
// Generated by Polycanal. Do not edit: regenerate instead.

import { action, defineContract, input } from '@polycanal/core';
import { rest } from '@polycanal/rest';
import { z } from 'zod';

export const PetSchema = z.object({
  id: z.string(),
  name: z.string(),
  parent: z.lazy(() => PetSchema).optional(),
});

export const api = defineContract({
  pets: {
    getPet: action({
      transport: rest.get('/pets/:petId'),
      input: input({
        petId: { source: 'path', schema: z.string() },
      }),
      output: PetSchema,
    }),
  },
});
```

## API programmatique

`@polycanal/codegen` est la couche sur laquelle reposent les importeurs et les adaptateurs serveur :

- `ContractDescription` : forme sérialisable d'un contrat (opérations avec des JSON Schemas, schémas nommés référencés
  par `#/schemas/<name>`) ;
- `describeContract(contract)` : description d'un contrat écrit en TS (côté input des schémas pour ce qui est envoyé,
  côté output pour ce qui est reçu) ;
- `mergeDescriptions(config, discovered)` : les opérations de la config l'emportent toujours ; les désaccords sont
  signalés ;
- `generateContractSource(description, { validation, bindings })` : source TypeScript, avec un driver de validation
  (`zodDriver` de `@polycanal/zod`) et des émetteurs de bindings (`restBindingEmitter` de `@polycanal/rest`).
